# Design Note: Improved debug CLI

Status: **proposal.** Refactor of `firmware/src/debug.rs` (the TT_DEBUG CDC
shell) into a structured command interpreter with a unified output format, a
command table that's trivial to extend (e.g. `ip` / `wifi` config for the
[LToUDP bridge](./ltoudp-design.md)), and an optional password-protected
telnet front-end once networking lands.

## 1. Why

The current shell (`debug.rs`) works but has grown ad-hoc:

- **Single-letter commands** dispatched in a big `match` inside
  `handle_input`, with a separate `Accumulating` state for the few that take
  arguments (`t`, `n`, `N`, `d`). Adding a command means editing three places
  (the idle match, the `dispatch_cmd` match, and `HELP`).
- **Inconsistent output**: replies are free-form — `OK\r\n`, `ERR:bad hex`,
  `NODE SET`, `DIR TIMEOUT`, `MONITOR ON`, bare hex dumps, multi-line status
  with `[nnnnnn]` timestamps on some lines but not others. Hard to parse from
  a host script.
- **No transport abstraction**: everything writes directly to `Cdc`. A second
  front-end (telnet) would have to duplicate the loop.

## 2. Goals

1. **Unified output format** — every response is machine-parseable and
   consistent, while staying human-readable in a terminal.
2. **Proper commands** — multi-character verbs with arguments, a single
   command table, auto-generated `help`.
3. **Easy to extend** — adding a command is one table entry + one handler fn.
   Concretely: land `ip`/`wifi` config without touching the parser.
4. **Optional telnet** — same command core reachable over TCP once the Pico W
   stack exists, gated behind a password.

Non-goals: full readline/line-editing, scripting/macros, persistent history.

## 3. Unified output format

Every command emits one or more **response lines**, then exactly one
**terminator line**. Line shape:

```
<TAG> <key>=<val> <key>=<val> ...
```

Terminators (always last, exactly one):

- `OK`                      — success, no payload
- `OK <key>=<val> ...`      — success with inline result
- `ERR <code> <message>`    — failure (machine code + human text)

Data/event lines use a stable prefix tag so a host can demultiplex the
combined command-reply + async-log stream on one CDC pipe:

| Tag    | Meaning                                  | Example                                    |
|--------|------------------------------------------|--------------------------------------------|
| `RX:`  | received frame, good CRC                 | `RX: t=001234 d=FF s=01 ty=01 BC=...`       |
| `RX!:` | received frame, bad CRC                  | `RX!: t=001235 ...`                         |
| `LOG`  | free-form async log line                 | `LOG core1 loops=998877`                     |
| `STAT` | one field of a status report             | `STAT recv good=10 bad=0 ar=3`              |
| `#`    | comment / banner (host ignores)          | `# TASHTALK-PICO <build> serial=...`        |

Rules:
- All lines `\r\n`-terminated (kept from today).
- Timestamps are an explicit field `t=<ms>` rather than a bare `[nnnnnn]`
  prefix, so every line is uniformly tokenisable.
- Async log/RX lines and command replies share the stream but never interleave
  *within* a line (the writer is line-atomic).
- A host driving the port programmatically reads until it sees an `OK`/`ERR`
  terminator; anything tagged `RX:`/`RX!:`/`LOG`/`STAT`/`#` in between is
  out-of-band and may also arrive when no command is pending.

This preserves the existing `RX:`/`RX!:` analyzer convention (CLAUDE.md →
Analyzer Mode) so current tooling keeps working; it just regularises
everything else around it.

## 4. Command model

Replace the single-letter `match` with a **command table**:

```rust
struct Command {
    name: &'static str,            // "tx", "node", "status", "ip", ...
    summary: &'static str,         // one line for `help`
    usage: &'static str,           // arg syntax
    min_args: u8,
    handler: CmdFn,                // async fn(&mut Ctx<'_>, &[Arg]) -> CmdResult
}

static COMMANDS: &[Command] = &[ ... ];
```

- A line is read until CR, split on whitespace into `verb` + args (heapless,
  bounded). The verb is looked up in `COMMANDS` (exact match, then unique
  prefix match so `st` → `status`).
- The handler receives a parsed context and returns `CmdResult`
  (`Ok(())` → emit `OK`, or `Ok(fields)` / `Err(code,msg)` → terminator).
- `help` is generated by walking the table; no separate `HELP` blob to keep
  in sync.
- **Back-compat**: keep the current single letters as aliases mapping to the
  new verbs during transition (`s`→`status`, `a`→`analyzer`, `m`→`monitor`,
  `b`→`bootsel`, `?`→`help`, `t`→`tx`, `d`→`directed`, `n`/`N`→`node`,
  `f`→`frames`, `c`→`clear`, `i`→`id`, `p`→`testframe`). A `compat` flag can
  later drop these.

### Initial verb set (maps 1:1 to today's behaviour)

| Verb        | Was | Args            | Notes |
|-------------|-----|-----------------|-------|
| `help`      | `?` | `[verb]`        | table-driven |
| `status`    | `s` | —               | emits `STAT ...` lines + `OK` |
| `clear`     | `c` | —               | clear counters |
| `monitor`   | `m` | `[on\|off]`     | explicit arg; bare = toggle |
| `analyzer`  | `a` | `[on\|off]`     | |
| `frames`    | `f` | —               | dump RX ring |
| `id`        | `i` | —               | USB serial |
| `tx`        | `t` | `<hex>`         | raw frame incl CRC via CSMA |
| `directed`  | `d` | `<dest> <hex>`  | RTS/CTS dialog |
| `node`      | `n`/`N` | `<set\|clr> <id>` | merge n/N into one verb |
| `testframe` | `p` | —               | known test frame |
| `bootsel`   | `b` | —               | reboot to BOOTSEL |

### New verbs enabled by the structure (future)

| Verb    | Args                          | Purpose |
|---------|-------------------------------|---------|
| `ip`    | `show` \| `dhcp` \| `static <addr> <mask> <gw>` | configure embassy-net |
| `wifi`  | `show` \| `join <ssid> <psk>` \| `forget`        | CYW43 station config |
| `ltoudp`| `show` \| `on` \| `off` \| `group <addr>`        | LToUDP bridge control |
| `passwd`| `<new>`                       | set telnet password (see §6) |

These are the payoff: each is *just a table entry + handler*, no parser changes.

## 5. Transport abstraction

Introduce a tiny trait so the command core is independent of CDC vs TCP:

```rust
trait Line {
    async fn write_line(&mut self, s: &[u8]) -> Result<(), IoError>;
    async fn read_chunk(&mut self, buf: &mut [u8]) -> Result<usize, IoError>;
}
```

- `CdcLine` wraps today's `Cdc` (`write_chunked` becomes `write_line`).
- `TcpLine` (later) wraps an `embassy_net::tcp::TcpSocket`.

The session loop — read line → parse → dispatch → emit terminator, plus
draining the `tt_log` channel for async `RX:`/`LOG` lines — is written once
against `Line` and reused by both front-ends. The line-buffer accumulation
(currently the `Accumulating` state machine over `CMD_BUF`) moves into a
reusable `LineReader` that yields complete lines.

Shared mutable state (`MONITOR_ENABLED`, `ANALYZER_MODE`, node bitmap) stays
where it is; only the I/O is abstracted. Note: the async-log stream is
currently a single `Channel`; if two sessions (CDC + telnet) run at once it
must fan out (either a `PubSubChannel` or "log goes to CDC only, telnet gets
command replies"). Decide when telnet lands — simplest first cut: **async
log/RX lines go to the CDC console only; telnet is request/response.**

## 6. Optional telnet (Pico W only)

Gated behind `#[cfg(feature = "net")]` and only meaningful once the Pico W
stack from [ltoudp-design.md](./ltoudp-design.md) exists.

- An `embassy-net` TCP listener on port **23** (configurable) accepts one
  session at a time (cheap; bounded RAM).
- **Password protection**: on connect, prompt `# password:` and read one
  line. Compare against a stored secret.
  - v1: secret is a `const`/build-time value or set via `passwd` and held in
    RAM (lost on reboot) — acceptable for a lab tool.
  - v2: persist to the last flash sector (RP2040 has no EEPROM; use a
    `embassy-rp` flash write of a small config struct). Store a hash
    (e.g. a keyed digest) rather than plaintext.
  - Rate-limit: after N failed attempts, drop the connection and add a delay.
- This is plain telnet (no TLS) — **LAN/lab use only**, document it as such.
  No raw-mode negotiation needed; treat it as a line stream (send `WILL ECHO`
  / `SUPPRESS GO AHEAD` or just ignore IAC sequences and strip `0xFF` bytes).
- Reuses the exact same command table via the `Line` trait — zero command
  duplication.

## 7. Migration plan (incremental, each step compiles & flashes)

1. **Introduce the response format helpers** (`reply_ok`, `reply_err`,
   `stat`) and convert existing handlers to emit `OK`/`ERR`/`STAT` — behaviour
   identical, output regularised. (No structural change yet.)
2. **Extract `LineReader`** from the current `Accumulating`/`CMD_BUF` logic.
3. **Introduce the `COMMANDS` table** and route the existing single letters
   through it as aliases; delete the giant `match`. `help` becomes
   table-driven.
4. **Add the `Line` trait**, wrap `Cdc` as `CdcLine`, move the session loop
   onto it. Still CDC-only.
5. *(after Pico W bring-up)* **Add `ip`/`wifi`/`ltoudp` verbs** — pure table
   additions.
6. *(after Pico W bring-up)* **Add `TcpLine` + telnet listener + `passwd`**.

Steps 1–4 are valuable on their own and have no dependency on the Pico W
work; do them first.

## 8. Risks / notes

- `debug.rs` uses several `static mut` globals (`CMD_BUF`, `FRAME_BUF`,
  `RX_LOG*`, `LOCAL_NODES`). The refactor is a good moment to wrap these in
  `SyncUnsafeCell`/`static_cell` to keep the single-core-0 access invariant
  explicit, but that's orthogonal — don't expand scope unless touching them.
- Keep `write_line` line-atomic (one CDC packet sequence per logical line) so
  command replies and async RX/LOG lines never split mid-line on the shared
  pipe.
- Prefix-matching verbs is convenient but can surprise scripts; exact match
  must always win, and `help` should list full names.
